## 一句话理解

高斯泼溅就是：**把场景表示成几十万个「带颜色、带透明度、被拉成椭球的三维高斯团」，渲染时把它们投影到屏幕上、按深度排序、从后往前半透明叠色**。

它既不是网格（没有顶点和三角形的连接关系），也不是 NeRF（不需要逐像素跑神经网络），而是一团**可以直接光栅化的点**。课程里那句「泼溅体可以实时渲染」，指的就是这条叠色链路足够便宜。

## 它到底在解决什么问题

3D 机器学习需要一种「既能被梯度优化、又能快速画出来」的表示。三个候选：

| 表示 | 对 AI 友好？ | 能实时渲染？ | 代价 |
| --- | --- | --- | --- |
| 网格 | 差（拓扑是离散决策） | 能 | 学不出连接关系 |
| NeRF / 隐式场 | 好（全连续） | 不能（逐像素查网络） | 渲染慢 |
| 泼溅体 | 好（全连续） | **能**（排序 + 叠色） | 没有拓扑，存储随细节涨 |

泼溅体踩中的正是中间那个空档：**渲染过程里没有神经网络，只有一串可微的代数运算**，所以既快又可训练。

## 一个泼溅体：14 个数字

课程 `unit3/what-is-it.md` 列了四个参数，展开成数字是：

| 参数 | 数字 | 存什么 | 直观含义 |
| --- | --- | --- | --- |
| 位置 | 3 | (x, y, z) | 椭球中心在哪 |
| 协方差 | 7 | 缩放 3 + 旋转四元数 4 | 被拉伸成什么形状、朝哪个方向 |
| 颜色 | 3 | RGB（或球谐系数） | 什么颜色 |
| 透明度 | 1 | α | 有多「实」 |

合计 **14 个浮点数**。注意协方差不直接存 3×3 矩阵（9 个数），而是存「缩放 + 旋转」再现场算 `Σ = (SR)ᵀ(SR)`：这样**天然保证矩阵半正定**（否则就不是合法的高斯），而且每个参数都能被梯度直接推动。

### 投影到屏幕：一个 2D 高斯

渲染时每个三维高斯被投影成屏幕上的二维高斯（EWA splatting，Zwicker 等 2001/2002 的公式，官方实现逐行沿用）：

```
cov2d = Tᵀ Σ T            # T 是投影的局部线性近似（Jacobian × 视图旋转）
cov2d[0][0] += 0.3        # 低通滤波：保证每个泼溅体至少约 1 像素宽
cov2d[1][1] += 0.3
```

像素离中心越远贡献越小，权重就是高斯函数本身：

```
α(像素) = α₀ · exp( −½ · dᵀ Σ₂d⁻¹ d )
```

沿主轴方向，距离中心 k 个 σ 处的 α 是固定倍数（实测/解析一致）：

| 距离 | α 相对 α₀ | 数值（α₀=1） |
| --- | --- | --- |
| 1σ | e⁻⁰·⁵ | 0.6065 |
| 2σ | e⁻² | 0.1353 |
| 3σ | e⁻⁴·⁵ | 0.0111 |
| 3.329σ | 1/255 | 0.00392（官方截断阈值，见下） |

官方实现把每个泼溅体的影响范围截断在 **⌈3σmax⌉ 像素半径**的方框里——框外的 α 已经 ≤ α₀ 的 1.1%，视觉上可以忽略。这个方框就是后面「为什么快」的关键。

## 渲染：投影 → 分块 → 排序 → 叠色

官方 CUDA 光栅器一共五步，交互页的「光栅化流水线」页签可以逐步开关：

1. **投影**：每个泼溅体算出屏幕坐标、2D 协方差、其逆矩阵（conic）和 3σ 半径；视深 z ≤ 0.2 的直接剔除。
2. **登记到分块**：屏幕切成 16×16 像素的块（tile），泼溅体只登记进它 3σ 方框碰到的那些块。
3. **排序**：所有（块, 泼溅体）对按 64 位键 `(tileID << 32) | floatBits(depth)` 做一次基数排序——块内自然就是从前到后。
4. **叠色**：每个块由 256 个线程（正好一块 16×16 像素）遍历自己的列表，逐像素做 α 混合：

   ```
   C += color · α · T        # 累加颜色
   T *= 1 − α                # 透射率衰减
   ```

5. **各种跳过**：`α = min(0.99, …)` 封顶；`α < 1/255` 直接跳过（低于一个 8-bit 色阶，看不见）；`T·(1−α) < 1e-4` 时该像素提前收工（后面再画也看不见了）。

最后 `out = C + T·背景色`。整帧没有任何「这个像素在不在三角形里」之类的离散判断——这正是它对 AI 友好的原因（见下节）。

### 这些常数从哪来

| 值 | 名字 | 出处与含义 |
| --- | --- | --- |
| 16 × 16 | 分块尺寸 | `config.h`：一个 CUDA block = 256 线程 = 一个 tile |
| +0.3 | 2D 协方差低通 | `forward.cu`：每个泼溅体至少约 1 像素宽，抑制微小泼溅体的走样 |
| 0.99 | α 上限 | `forward.cu`：保证 1−α ≥ 0.01，透射率必然衰减 |
| 1/255 | α 下限 | `forward.cu`：低于一个 8-bit 色阶即不可见，跳过 |
| 1e-4 | 透射率下限 | `forward.cu`：像素提前结束 |
| z ≤ 0.2 | 近面剔除 | `forward.cu`：相机后方/贴脸的泼溅体丢弃 |
| ±1.3·tanfov | Jacobian 钳制 | `forward.cu`：把 EWA 线性化限制在视锥核心内 |

## 为什么「可微分 = 对 AI 友好」

课程的说法是：三角形光栅化包含离散决策（像素在不在三角形内、遮挡关系），神经网络讨厌离散；泼溅体的每个像素值都是参数的**光滑公式**，所以 `∂图像/∂参数` 存在，梯度下降可以直接「挪动、拉伸、改色」每个泼溅体去逼近照片。

交互页的「为什么对 AI 友好」页签把这件事做成了一个可玩实验：给一张目标图，用 16 个二维泼溅体去拟合它，优化器是 Adam（原始论文同款），梯度是解析反传的（与有限差分对拍，最大相对误差 1.3e-8）。实测：

- 网格状初始化（类似 SfM 给点）：loss 从 2.93e-2 降到 **1.46e-5**（1200 步），与目标图最大像素差 0.046——肉眼已分不出。
- 换成 6 个随机初始化的泼溅体：落在空白处的泼溅体**梯度恒为 0，永远不动**（dead zone），loss 卡住。

第二个现象解释了原始论文的两个设计：**用运动恢复结构（SfM）的点做初始化**（保证一开始就落在有信号的地方），以及训练中的**自动稠密化 / 剪枝**（哪里欠拟合就在哪里分裂新泼溅体，哪里长期透明就删掉）。

整条链里真正不光滑的只有三处：两个 α 阈值和排序顺序。它们都是「少数、无害」的离散点（梯度在阈值处取 0 即可），与三角形光栅化「每个像素都要做包含判断」是量级上的差别。

## 训练：从照片到泼溅体

原始论文（Kerbl et al., SIGGRAPH 2023, arXiv:2308.04079）的流程：

1. **SfM 初始化**：用传统运动恢复结构得到稀疏点云，每个点变成一个初始泼溅体。
2. **逐视图渲染 + 损失**：对每张训练照片渲染一帧，与真值比 MSE（再加感知损失 LPIPS），反传更新全部参数。
3. **稠密化 / 剪枝**：每 100 步检查一次梯度大的泼溅体（欠拟合）做分裂/放大；长期透明度低的删除；每 3000 步重置一次透明度防止「幽灵点」。
4. **视角相关颜色**：用 3 阶球谐（48 个额外系数/点）表示「从不同方向看不一样」的效果。

官方默认超参（`arguments/__init__.py` 实测）：`sh_degree=3`、`densification_interval=100`、`opacity_reset_interval=3000`、`densify_grad_threshold=0.0002`、`percent_dense=0.01`、位置学习率 1.6e-4 → 1.6e-6（30k 步衰减）。

## 生成式 3D：LGM 把训练也省了

课程第 2/5 单元用的 [LGM](https://huggingface.co/ashawkey/LGM)（arXiv:2402.05054）是前馈路线：多视图扩散模型先画 4 个视角，一个 U-Net 直接**回归出泼溅体参数**，不再逐场景优化。实测其配置：

- 每个视角输出 `splat_size × splat_size` 个泼溅体：small/lrm 配置 64² × 4 视角 = **16 384** 个，big 配置 128² × 4 = **65 536** 个。
- 每个泼溅体 **14 个浮点数**（位置 3 + 透明度 1 + 缩放 3 + 旋转 4 + RGB 3），`sh_degree=0`——所以 LGM 的泼溅体颜色不随视角变化。
- 激活函数：位置钳到 ±1、缩放 = 0.1·softplus、透明度 = sigmoid、旋转归一化、颜色 = 0.5·tanh+0.5。

课程流水线（unit2 多视图扩散 → unit3/5 LGM → 可选 splat→mesh）就是这条链。

## 存储：一个点多少字节

| 格式 | 字节/点 | 内容 |
| --- | --- | --- |
| LGM 运行时 | 56 | 14 个 float32（本页渲染的就是它） |
| `.splat`（网页格式） | 32 | 位置 f32×3 + 缩放 f32×3 + rgba u8×4 + 旋转 u8×4 |
| 3DGS 训练参数 | 236 | 位置 3 + 球谐 48 + 透明度 1 + 缩放 3 + 旋转 4 = 59 float32 |
| 3DGS `.ply` 落盘 | 248 | 上述 59 个 + 3 个从不使用的法线（历史遗留 PLY 头） |

按点数换算：16 384 个泼溅体（LGM small）≈ 0.9 MB（56 B/点）；100 万个 ≈ 56 MB；照片级场景常见数百万点，所以编辑器都在做剪枝和量化。

## 为什么快：分块省了多少活

暴力做法是「每个泼溅体 × 每个像素」，即 N·W·H 次高斯求值。分块 + 3σ 截断后，只有方框碰到该块的泼溅体才会被求值。用本页核心实测（随机椭球点云）：

| N | 分辨率 | 暴力像素-泼溅对 | 分块写入 | 省掉 |
| --- | --- | --- | --- | --- |
| 200 | 64² | 819 200 | 532 | 1540× |
| 200 | 128² | 3 276 800 | 1 058 | 3097× |
| 1000 | 64² | 4 096 000 | 2 606 | 1572× |
| 1000 | 128² | 16 384 000 | 5 290 | 3097× |

再叠加两个提前退出：α < 1/255 跳过（上表 N=1000 / 64² 场景实测约 58 万次/帧）、T < 1e-4 像素收工。透射率的算术很直白：α=0.5 的泼溅体叠 14 层后 T = 6.1e-5，像素就已经「不透明到可以停」了——**一个像素永远只读它前面那少数几个泼溅体**。

代价也要说清：分块与「全图暴力遍历」的结果**不完全相同**——3σ 方框外的贡献被截掉了。实测同一场景两条路径的最大像素差 0.0098（0.058% 的像素超过 1/255 色阶），即截断误差在 8-bit 显示下基本不可见。这是速度换精度的有意取舍。

## 对比与边界

| | 网格 | NeRF / 隐式场 | 高斯泼溅 |
| --- | --- | --- | --- |
| 存什么 | 顶点 + 三角形 (+uv/法线) | 隐式场 f(x,y,z) | N 个独立三维高斯 |
| 拓扑 | 显式连接关系 | 提取前没有 | 永远没有 |
| 渲染 | 三角形光栅器 | 逐像素跑网络 | 排序 + α 混合（本页） |
| 实时 | 能（整个生态） | NeRF 级画质不能 | **能** |
| 像素可训练 | 难 | 能 | 能 |
| 编辑/动画 | 工具成熟 | 难 | 新兴（4DGS、物理混合） |

泼溅体不适合的地方：

- **没有水密表面**：碰撞、CAD、3D 打印、UV 展开仍要网格——所以课程 unit4 有 splat→mesh 转换器。
- **存储随细节涨，不随拓扑省**：一面白墙和一只毛茸茸的动物，屏幕细节相同就花同样多的泼溅体。
- **视角相关效果**要球谐（+48 float/点）或额外网络。
- **伪影是「糊」不是「裂」**：floaters、针状物、大视角变化下的「泼溅汤」。

## 血统一行流

Surface splatting（Zwicker et al. 2001）→ EWA splatting（2002）→ 可微点渲染一系列工作 → **3D Gaussian Splatting**（Kerbl et al., SIGGRAPH 2023）→ 前馈生成器 **LGM**（2024）。本页的投影数学就是 2001/2002 那套 EWA 公式，二十多年没变。
